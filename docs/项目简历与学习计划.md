## 0. 背景叙事（怎么讲"项目从哪来"）

面试讲项目的第一句要先交代来源，这是真实性最强的锚点：

> "这个项目源头是我们实验室的一个流程平台系统（algp，Spring Boot + 内嵌 Camunda 流程引擎 + MySQL/RabbitMQ）。它出问题时我们要手工登机器翻日志查 MySQL 连接池，我就想给实验室做一个能自动值守的运维 Agent。第一版是专门贴着 algp 做的：为它的内嵌式流程引擎单独写了 Camunda 连接器，健康判断直接看 algp-web actuator/health 里的 processEngine/jobExecutor 细节组件。做出效果后我把整套能力抽象成多租户 SaaS——任何业务系统注册进来就能用，现在一台机器上同时接入 algp、svom、hxmt 三个真实系统，演示栈一键拉起（stack-launcher.sh）。"

> 写作口径：**直接承认实验室背景**，不藏。话术要点是把"实验室"立刻对齐到"真实运行中的业务系统"——即主动强调它**不是消融实验或玩具 Demo，而是有真实外部接入方、真实故障场景、并通过开放 Token 长期接入的存量系统**，这属于运维 Agent 天然适合的落地场景（科研机构 IT 系统的智能运维），含金量来自真实性与评测数据而非标榜规模。

这个叙事的三个加分点：
1. **解决的是真问题**——实验室系统出故障人肉排查，不是"为了做 Agent 而 Agent"；
2. **有真实外部接入方**（不是玩具 Demo）：algp 是通过平台开放 Token（`/openapi/v1/*` + `X-System-Code`）接入的，回写消息状态、上传错误日志生成告警、提交生产日报——这对应简历上"开放接入体系"那一条的实证；
3. **泛化架构的工程决策**：从"一个定制品"演进为"平台 + 连接器 SDK"（agent 定制写 → 描述符模式 descriptor → 采集器共用 SDK），这是面试官最爱听的"架构演进"故事。

## 三、STAR 话术（3 分钟面试叙述版）

- **S（情境）**：实验室流程平台系统 algp（Spring Boot + 内嵌 Camunda）故障排查全靠人：登机器翻日志、查 MySQL 连接池、看 Camunda 流程引擎是否卡死；市面上的 AI 只停留在"问答"，不能真正动手，也没法证明"Agent 排查是否靠谱"。
- **T（任务）**：做一个多租户平台，让 AI Agent 替代一线巡检与初诊；关键约束是——只读优先、写操作必须人工审批、诊断质量必须可量化。
- **A（行动）**：
  1. 架构：FastAPI 控制面 + Vue3 控制台 + 客户内网出站采集器（WebSocket 网关），平台永不入站，解决了"无法访问客户私网"的安全与合规问题；
  2. Agent：Pydantic AI 跑 ReAct 循环，11 个工具 + 8 类 Playbook + pgvector RAG（HNSW 余弦 + 关键词降级）；
  3. 治理幻觉与成本：模型路由（轻问走 cheap 模型，P0 关键词升 Reasoner）+ 子Agent 上下文隔离 + token 预算与 usage limits；
  4. 安全闭环：LangGraph 审批闸 + AsyncPostgresSaver + 回查节点验证恢复；
  5. 评测：112 条用例真实 Docker 故障注入，成功率/RCA/Tool-F1/幻觉率/token 五维打分，消融决定功能去留。
- **R（结果）**：成功率 100%（第 3 轮）、幻觉 0%、token −16.4%；形成"负结果档案"（纯语义路由更差）体现工程判断力。

## 五、项目真实难点清单（面试"你遇到过什么难题"素材）

按"痛点 → 我的解法 → 数据佐证"组织，每条都出自真实代码/评测记录：

1. **LLM 诊断的"幻觉维修步骤"风险**
   - 之前：Agent 会硬编不存在的日志/指标细节。
   - 之：所有结论必须引用工具证据；Playbook 拒识路由"低于阈值不硬塞剧本"；评测把幻觉率做成一票否决指标 → 长期 0%。

2. **纯语义检索不靠谱（负结果也是结果）**
   - 之前：纯 Embedding 路由命中率仅 42.3%，低于关键词 59.8%。
   - 之：三级混合路由（关键词直采→语义兜底→拒识），并在评测报告里保留负结果，体现"数据驱动而非信仰 RAG"。

3. **长任务把主 Agent 上下文撑爆（成本失控）**
   - 之前：主 Agent 逐一探查 6 个服务，15.1k token/次。
   - 之：取证子Agent 上下文隔离 + 共享工具缓存 + 紧凑证据摘要回传 → 12.6k（−16.4%），成功率还升到 98.2%。
   - 诚实代价：串行子Agent 使延迟 4.9s→12.7s，缓解方向已写入报告（子Agent 内批量并行）。

4. **"让 AI 真正动手"的安全红线**
   - 之前：AI 只能总结问题，无法执行重启等操作；直接放开太危险。
   - 之：能力目录（ActionSpec 白名单）+ LangGraph interrupt 停下等人审批 + AsyncPostgresSaver 挂起态跨重启存活 + 执行后自动回查，restart 仅限已注册 systemd unit。

5. **客户内网不可达 → 平台永不入站的采集器架构**
   - 之：采集器出站 WebSocket 长连 + 指令下发；token 一次可见、SHA256 落库。

6. **数据库从 SQLite 到 PostgreSQL 的生产化改造**
   - 之：16 个 Alembic 迁移（含 pgvector 扩展与 knowledge_chunks）、1046 行数据迁移核对一致、启动自动 `upgrade head`；LangGraph 检查点换成 AsyncPostgresSaver。

7. **多租户 + 外部系统接入的权限边界**
   - 之：org_id 行级隔离 + 系统级 Token（scope/过期/禁用）+ request_id 幂等去重 + 敏感字段 Fernet 加密与响应掩码。

8. **评测驱动而非感觉驱动**
   - 之：四轮方法学迭代每一轮都以"离线评测数字变化"为唯一验收标准，形成可复盘的实验档案（docs/evals/）。

## 六、面试高频问答（含追问预案）

**Q1：你的 Agent 怎么决定用哪个工具？会不会瞎调？**
A：Pydantic AI 的原生 tool-calling（类型安全签名）+ 工具级 memoize 缓存去重；评测用 Tool-F1（0.416→0.456）度量"该调没调/调错"。追问"为什么 F1 不高"：部分用例证据足够、合理地少调工具，是打分口径偏严，可作为下一轮改进点。

**Q2：怎么防止幻觉？**
A：三层——工具证据强引用、Playbook 拒识（不硬塞弱相关 runbook）、评测幻觉率否决。评测所有轮次幻觉 0%。

**Q3：RAG 为什么不用 LangChain？向量库为什么选 pgvector？**
A：需求是"文档+向量+运维表同库"，pgvector 附着在已有 Postgres，免引入独立向量库运维；HNSW 余弦 + 按 system_id 十级过滤隔离租户；embedding 失败自动降级关键词检索，指标连续性不中断。

**Q4：LangGraph 为什么用它？**
A：审批闸天然是个 interrupt 状态机：analyze →(interrupt)→ execute → verify；checkpoint 持久化用官方 AsyncPostgresSaver，服务重启不丢挂起审批，且有内存降级兜底。

**Q5：上下文窗口/成本怎么管？**
A：子Agent 隔离（−16.4% token）、模型按关键词路由（P0 才上 Reasoner）、usage limits 硬中断、Langfuse 全链路观测。

**Q6：MCP 为什么做，怎么做的？**
A：把 8 个只读运维工具封装成标准 MCP Server（stdio/SSE），使其能脱离平台被 Claude Desktop/Cursor 复用——体现工具层与 Agent 层解耦。

**Q7：为什么先做定制品再做平台，而不是一开始就设计成 SaaS？**
A：诚实讲是演进而来的：algp 是当时唯一明确的用户，贴着真实故障场景先把诊断 Agent、Playbook、审批闭环跑通；跑通后才发现核心资产是"只读工具层 + Playbook + 评测体系"，于是把连接器抽成 SDK（base 抽象 + 描述符从 DB 读配置），把诊断/审批/消息全挂到 system/org 维度上，才有了多租户平台。先有真问题再有抽象，顺序反了容易过度设计。为 algp 内嵌流程引擎定制的 Camunda 连接器就是这一时期的产物——它不是通用六连接器能覆盖的。

**Q8：如果流量/租户规模 ×10，什么先坏？**
A：诚实答：①同步诊断接口连接池与 LLM 并发限流；②WS 网关单点；③Celery 巡检频率与 Redis broker 容量；④评测集要重采样。这说明你有容量视角。

**Q9：这个项目的 MTTR/在线效果有数字吗？**
A：「平台以离线评测闭环为准（112 条，成功率 100%、幻觉 0%）；在线 MTTR 未做 A/B 统计，正在设计接入企业工单数据后补充。」不编数字。

**Q10：技术上最大的收获？**
A：三条：非确定性系统必须配确定性护栏（白名单/审批/回查）；Agent 质量要靠评测体系持续验证而非 prompt 手感；上下文是最贵的资源（引出子Agent 的数据）。
